The Archmage's Trial

Classes, inheritance, and polymorphism, together at last

Def The Trial

The Archmage will only grant the title of OOP Master to a wizard who can design a small class hierarchy from nothing — using a parent class, at least one child class, a private attribute, and polymorphism across a list of mixed objects.

✕ Challenge
  • Create a parent class CampActivity with a constructor storing name and a private attribute __spots_left (starting spots available). Add a method book_spot() that reduces __spots_left by 1 if any are left (printing confirmation), otherwise prints "Fully booked". Add a method info() that prints the activity name and remaining spots.
  • Create a child class OutdoorActivity that inherits from CampActivity, adds its own attribute weather_risk (str, e.g. "low"/"high"), and overrides info() to call the parent's info() with super() and then print the weather risk on an extra line.
  • Create at least one plain CampActivity object (e.g. "Coding Workshop") and at least one OutdoorActivity object (e.g. "Dune Hike", weather_risk="high").
  • Put every activity object into a single list and loop through it calling .info() on each one, relying on polymorphism — the loop should not check what type any object is.
  • After the loop, call book_spot() a few times on one of the objects (including once when it should be full) to prove the encapsulated spot count is being protected correctly, printing info() again at the end to confirm.
Only OutdoorActivity needs its own info() — CampActivity's version already works fine for itself and gets reused by super().info() inside the child.
