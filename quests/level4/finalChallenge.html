Challenge 1 · worked example 
# Mama Ndeshi sells vetkoek at Post Street Mall in Windhoek.
# Before market day, she wants to know how many batches she
# can bake using ONLY what's already in her pantry.
#
# One batch needs f kg flour, s kg sugar, and o litres of oil.
# Her pantry holds F kg flour, S kg sugar, and O litres of oil.
#
# Input (two lines):
#   F S O   — pantry stock
#   f s o   — recipe requirements per batch
#
# Input:
#   9 5 6
#   3 2 2
# Output:
#   2
✎ Solution

Each ingredient on its own limits how many batches are possible — flour alone allows F // f batches, sugar allows S // s, oil allows O // o. The pantry can only support as many batches as its tightest ingredient, so the answer is the smallest of the three.

F, S, O = map(int, input().split())
f, s, o = map(int, input().split())

batches = min(F // f, S // s, O // o)
print(batches)

For the example above: 9 // 3 = 3, 5 // 2 = 2, 6 // 2 = 3 — the smallest is 2, so Mama Ndeshi can bake 2 full batches.

2 Challenge 2 — No Solution Given

Write a program that reads Mama Ndeshi's pantry stock, her recipe, and her budget, then prints the maximum number of full batches she can bake — buying whatever's missing, as long as she stays within budget.

Try increasing the batch count one at a time, starting from zero. For each candidate number of batches n, work out how much of each ingredient she's short of using max(0, n * need - have), multiply each shortfall by its price, add the three costs together, and check whether the total fits within budget R. Keep increasing n while it's still affordable — the last affordable n is your answer. A while True: loop that breaks the moment a candidate becomes unaffordable works well here.

Try these cases and check your output matches:
2.a  6 3 4 / 3 2 2 / R=0  → 1
2.b  6 3 4 / 3 2 2 / R=40 → 2
2.c  6 3 4 / 3 2 2 / R=150 → 3
2.d  0 0 0 / 3 2 2 / R=300 → 2
